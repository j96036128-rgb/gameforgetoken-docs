# How to Submit a Build Request

This guide explains how game builders can request structured support through GameForgeToken.

---

## Important Disclaimers

Before submitting, please understand:

- **The GFT token is not live.** No token exists on any blockchain.
- **No payments are guaranteed.** Build Requests are a coordination tool, not a funding mechanism.
- **All requests are reviewed manually.** Submission does not guarantee acceptance or response.

---

## What Is a Build Request?

A Build Request is a formal way to ask for structured support on your game project. This might include:

- Playtesting coordination
- Technical review of your prototype
- Documentation feedback
- General project guidance

Build Requests help match builders with contributors who can provide meaningful input. They are logged publicly in the Participation Ledger for transparency.

---

## How to Submit (5 Steps)

### Step 1: Read the Documentation

Review the [Whitepaper](whitepaper.md) and [Workspace Model](participation-ledger/WORKSPACE-MODEL.md) to understand how GameForgeToken operates. This ensures your request aligns with the project's scope.

### Step 2: Go to GitHub Issues

Navigate to the Issues tab of this repository:

https://github.com/j96036128-rgb/gameforgetoken-docs/issues

### Step 3: Click "New Issue"

Select the **Build Request Submission** template from the available options.

### Step 4: Complete the Form

Fill in all required fields:

- Your project name and contact details
- Type of support you're requesting
- Current stage of your project
- What specific feedback you need
- Your timeline

Tick the checklist items to confirm you've read the relevant documentation.

### Step 5: Submit

Click **Submit new issue**. Your request is now logged and visible publicly.

---

## What Happens Next

1. **Review** — Your request is reviewed manually by core contributors. This may take several days.
2. **Response** — If your request is accepted, you'll receive a comment on the issue with next steps.
3. **Coordination** — Accepted requests are matched with available contributors based on skills and availability.
4. **Logging** — All activity is recorded in the Participation Ledger for transparency.

If your request is declined or deferred, you'll receive a brief explanation on the issue.
